# ZL2 Controls & Desktop-Style Input Bridge Design (Stage L-B / B1)

This document specifies the Stage L-B input architecture connecting Zalith Launcher 2 (ZL2)'s Compose control overlay, virtual/physical mouse, hardware keyboard, gamepad, and soft keyboard bar to the embedded `engine/starling` Rust engine (`fa548eb7abe91c194d3780e4580b9746323cd606`, `blaze-embedded` build).

---

## 1. Engine Input Classification: Shared Desktop Core vs Android-Only Layer

Investigation of `engine/starling` (`horizon-client-input` and `horizon-client`) confirms that the pinned commit (`fa548eb7ab`) **already has a complete shared desktop input path** (`winit::event::WindowEvent` + `winit::event::DeviceEvent::MouseMotion`) that drives all gameplay, cursor grab, hover/click in menus, text boxes, hotbars, and scrollbars. There is no need to invent a parallel input state machine.

**Where desktop input state is updated**:
1. Key presses/releases & modifiers -> `Game::handle_window_event` (`ModifiersChanged`, `KeyboardInput`) -> updates `self.modifiers`, `self.physical_keys`, `self.keys`, `self.toggles` (`horizon_client_input::keymapping::KeyState`), plus screen/chat/sign/book/search handlers.
2. Absolute pointer & hover/clicks (ungrabbed) -> `Game::handle_window_event` (`CursorMoved`, `MouseInput`, `MouseWheel`) -> updates `self.cursor` (GUI coordinates `position / b.scale`), triggers `self.capture(true)` when clicking on `Screen::Playing`, or clicks/drags UI widgets cleanly.
3. Camera look deltas (grabbed) -> `self.mouse.on_move(0.0, 0.0, dx, dy, true, true)` (`game.rs:16338`) -> consumed every frame by `Rotation::turn`.

**Crucial finding**: `CallbackBridge.java` loads `libpojavexec.so` in its `static {}` initializer (`CallbackBridge.java:540`). In the `:rust` process (`RustActivity`), `libpojavexec.so` must NEVER be loaded. Therefore, `BlazeInputRouter` introduces a clean `BlazeInputSink` interface:
- `JavaCallbackInputSink` (default in `main` / `:jvm` / Java runtime): forwards directly to `CallbackBridge` — **100% zero behavior change for Java Edition.**
- `RustInputBridge` (active in `:rust` process when Desktop Input Mode is on): implements `BlazeInputSink` over `BlazeNativeBridge` JNI without touching `CallbackBridge` at all!

## 3. Target Architecture (`B2`–`B6`)

### 3.1 Minimal Rust Input Injector Queue (`B2`, `engine/patches/0009-blaze-input-injector.patch`)
- Fixed-size lock-free/Mutex ring buffer (`const INPUT_QUEUE_CAP: usize = 512`) inside `horizon-client-render/src/android_runtime.rs` (zero per-event heap allocation: inline `BlazeInputEvent` `Copy` enum with `utf8: [u8; 4], utf8_len: u8` for characters instead of `String`):
  1. `Key { glfw_key: i32, unicode_char: u32, mods: i32, pressed: bool }` -> maps via complete `glfw_keycode_to_winit(glfw_key)` table to `winit::keyboard::KeyCode`, attaches UTF-8 char if printable, calls `Game::handle_window_event(events, id, WindowEvent::ModifiersChanged(..))` + `WindowEvent::KeyboardInput { ... }` cleanly.
  2. `MouseButton { glfw_button: i32, mods: i32, pressed: bool }` -> maps GLFW mouse buttons `0..4` (`Left`, `Right`, `Middle`, `Back`, `Forward`) to `winit::event::MouseButton` and dispatches `WindowEvent::MouseInput`.
  3. `CursorPos { norm_x: f32, norm_y: f32 }` -> scaled inside `Game` against actual renderer surface dimensions `[r.config.width, r.config.height]` (`PhysicalPosition::new(nx * w, ny * h)`), then dispatched as `WindowEvent::CursorMoved` so `render_scale_percent < 100` still hits buttons pixel-accurately!
  4. `Scroll { dx: f32, dy: f32 }` -> dispatched as `WindowEvent::MouseWheel { delta: MouseScrollDelta::LineDelta(dx, dy) }`.
  5. `Char { codepoint: u32 }` -> dispatched as `WindowEvent::Ime(Ime::Commit(..))` / key text when not already covered by `Key` (e.g. non-ASCII Unicode / emoji / CJK from `HidableInputLayout`).
  6. `AndroidBack` -> invokes `Game::pad_back()` cleanly so Stage L-A's title-screen exit and in-game pause menu stay intact even while `blaze_desktop_input` intercepts `KEYCODE_BACK`.
- **Coalesced Mouse Delta**: Separate atomic/mutex accumulator (`pending_delta_x: f64`, `pending_delta_y: f64`) that sums all incoming `sendCursorDelta(dx, dy)` calls between frames (`O(1)` overhead, zero ring growth), drained once per frame in `Game::idle` and fed directly into `self.mouse.on_move(0.0, 0.0, dx, dy, true, true)` when `self.captured && self.screen == Screen::Playing && self.focused && self.pending_save.is_none()`.
- **Cursor Grab Callback**: `Game::capture` notifies Java via `platform::notify_cursor_grab(self.captured)` -> JNI `RustActivity.onCursorGrabChanged(boolean grabbing)` -> `RustInputBridge.onCursorGrabChanged(grabbing)` -> updates `ZLBridgeStates.changeCursorMode(CURSOR_DISABLED or CURSOR_ENABLED)` so ZL2's `SwitchableMouseLayout`, hotbar touch passthrough, and gamepad camera stick immediately switch between menu cursor and gameplay look!

### 3.2 Single Soft Keyboard Owner (`B4`)
- **Chosen Owner**: **ZL2 (`HidableInputLayout` + `LWJGLCharSender` + hardware `dispatchKeyEvent`)** owns soft keyboard input when Desktop Input Mode is active.
- **Engine `native_ime` (`crates/horizon-client/src/android/native_ime.rs`)**: remains disabled/hidden (`platform::show()` / `android_show_keyboard()` are no-ops and `native_ime::hide()` is enforced) when `blaze_desktop_input_enabled()` is `true`.
- **Rationale**: Prevents two Android `InputMethodManager` sessions from fighting over `NativeActivity` focus, lets users toggle ZL2's familiar chat/text bar (`TextInputMode`), automatically hides the bar when cursor grab engages (`cursorMode == CURSOR_DISABLED`), and supports non-ASCII text via `BlazeNativeBridge.nativeInjectChar`. Switching on the Developer Mode fallback toggle re-enables `native_ime`.

### 3.3 Overlay Hosting & Edge Cases (`B5`–`B6`)
- `RustActivity` (which extends `android.app.NativeActivity` for winit glue) creates an internal `NativeLifecycleOwner` (`LifecycleOwner`, `SavedStateRegistryOwner`, `ViewModelStoreOwner`, `OnBackPressedDispatcherOwner`), sets the ViewTree owners on `window.decorView`, and mounts a transparent `ComposeView` on top via `addContentView(...)`.
- Window cutout mode (`SHORT_EDGES`), safe display insets (`WindowInsets.Type.displayCutout()`), edge-gesture exclusion (`systemGestureExclusionRects`), SAF document picker (`4101`), and Stage L-A exit callback (`onEngineExit`) remain preserved on `RustActivity`.
- `RustActivity.dispatchKeyEvent` / `dispatchGenericMotionEvent` handle hardware keyboard, gamepad (`GamepadViewModel` reusing ZL2's controller->keyboard/mouse mapping), and mouse back-button -> right-click interception before passing through when fallback toggle is enabled.
- When **Desktop Input Mode** is ON (default):
  - Engine drops raw OS `WindowEvent::Touch`, OS `KeyboardInput`/`MouseInput`/`CursorMoved`/`MouseWheel`/`ModifiersChanged`/`Ime`, and OS `DeviceEvent::MouseMotion` in `ApplicationHandler` (`window_event`/`device_event`) so events come strictly from the `RustInputBridge` queue (preventing double-firing) while keeping lifecycle events (`Resized`, `Focused`, `RedrawRequested`, `CloseRequested`, `ScaleFactorChanged`) intact.
  - Engine forces `keyboard_mouse_input() == true`, `touch_visible() == false`, skips `draw_goy_hud`, `touch.draw`, `touch_ui.draw`, and `draw_pointer` (since ZL2 draws `MousePointer`).
- **Fallback Toggle (`B6(b)`)**: Developer Mode switch **"Use engine touch controls (fallback)"** (default `false`), persisted in `AllSettings` and synced at launch/startup (`blaze_engine_settings.json` + JNI configure). When `true`, `RustActivity` hides the ZL2 overlay and lets touches/keys go natively to the engine's compiled-in touch controls.

### 3.4 Risks & What Cannot Map cleanly
1. **`NativeActivity` pointer capture with ComposeView**: Android `requestPointerCapture()` requires focus on the View receiving `OnCapturedPointerListener` inside `TouchpadLayout`. Testing on physical device (`SM-N975F`) is needed to confirm Compose `SimpleMouseCapture` acquires capture over `NativeActivity`'s underlying surface.
2. **IME Preedit / CJK Composition**: `HidableInputLayout` commits completed text (`onSend` -> `sendChar`) rather than inline preedit underlines inside Minecraft text boxes (`Ime::Preedit`). Completed characters work via `Ime::Commit`.
3. **ZL2 Control Editor Live Editing in `:rust`**: Hosting `ControlEditor` inside `RustActivity`'s `ComposeView` requires a `ViewModelStoreOwner` (provided by `NativeLifecycleOwner`), and edits save cleanly to the control layout JSON file on disk.
4. **Control-specific Java features (`Modrinth`/`SDL direct gamepad`)**: Direct SDL buffer (`CallbackBridge.sGamepadButtonBuffer`) is not active in the Rust engine; gamepad works through ZL2's `GamepadKeyListener` + `GamepadStickMovementListener` + `GamepadStickCameraListener` mapping to keyboard/mouse/delta cleanly.
